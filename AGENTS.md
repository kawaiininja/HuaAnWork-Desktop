# DSH Desktop repository rules

This repository owns the desktop product around an unmodified DeepSeek Harness checkout.

## Prerequisites and setup

- Use Node.js `^22.19.0` or `>=24.0.0` and the root Yarn `4.18.0` release through Corepack.
- Initialize the pinned upstream checkout with `git submodule update --init --recursive`.
- Install root dependencies with `corepack yarn install --immutable`.

## Build, run, and verify

- Start the desktop development workflow with `corepack yarn dev`.
- Build the desktop package with `corepack yarn build`.
- Root build, dev/start, and packaging commands refresh `dshmarket` from npm `latest` for HuaAnWork via `corepack yarn market:prepare`. Commit its exact dependency versions, Desktop compatibility patch, and lockfile together. `corepack yarn market:check` verifies freshness without writes; offline lookups or incompatible patches fail rather than silently retaining an old market. Installed apps do not hot-update executable plugins on launch.
- Before each release, run `corepack yarn aa:prepare-release` to build the latest official Agents Anywhere `main` for the HuaAnWork desktop channel. Commit the resulting artifact, provenance, manifests, and lockfile before packaging. Signed macOS releases and root Windows distribution commands verify freshness and installed versions; `DSH_AA_SOURCE_REF=pinned` is no longer supported.
- Run unit tests with `corepack yarn test`.
- Run type checking with `corepack yarn typecheck`.
- Run the complete headless gate with `corepack yarn check`.
- Develop and validate Desktop features directly in `dsh-plugin-huaanwork/`. It is the only desktop source tree in this repository: there is no beta-first mirror and no variant-alignment gate.
- Run upstream operations through the root scripts, such as `corepack yarn upstream:build`.
- Upstream synchronization is selective review, not a whole-repository merge: `desktop-upstream.json` pins `reviewedCommit` + `watchedPaths`, and `node scripts/upstream-sync-dashboard.mjs` lists every pending upstream commit with each direct file classified. The basis is the `upstream` remote (`anywhere-labs/dsh-desktop`), **not** fork `origin/master` and **not** the local mirror's `master`. `docs/upstream-sync.md` §§1-7 are the live rules; §§8+ are historical merge-era snapshots.

- `deepseek-harness/` is a pinned upstream Git submodule. Never edit files inside it from a desktop feature branch.
- `dsh-plugin-huaanwork/` is the only desktop source tree: it owns the Cordis Host and Client faces, the Electron bootstrap, packaging, and release tests for the product. The retired Stable, Beta, and Next trees were deleted on 2026-10-30; their upstream package names survive only as historical identity (see `DESKTOP_RELEASE_IDENTITIES`) and as upstream npm contracts.
- `dsh-community-fabric/` owns the community interoperability RFC. Until schemas and a reviewed reference adapter exist, it remains a private documentation scaffold and must not declare loadable DSH or package entry points.
- `dsh-community-market/` owns the community-market shell. Its runtime is implemented with a **public-network security model** (`restricted-http.ts` blocks intranet addresses; `createNpmRegistryVerifier` trusts npmjs). The M5 intranet market does **not** reuse its runtime routes (spec §14 第十轮 第 39 条, review D8); the huaanwork intranet consumer face is self-implemented in the wrapper (`dsh-plugin-huaanwork/src/huaanwork-host/market/`, 7 off-table routes), importing only the `dsh-community-market/contracts` provider-page schemas. The upstream package itself remains zero-modified.
- The outer repository and all owned packages use the root Yarn release with `nodeLinker: node-modules`.
- The upstream submodule keeps its own pnpm workspace. Run upstream commands through the root `upstream:*` scripts, whose Yarn portable-shell commands enter the submodule before invoking Corepack.
- Compatibility mode must run the upstream default client without overrides. Advanced presentation belongs to desktop-owned client plugins and may replace documented slots or services through profile composition.
- Keep graphical application launch explicit. Builds, typechecks, unit tests, and Loader smokes must remain headless-safe.
- Commit before major changes of direction and keep the submodule pin update separate from desktop behavior changes.
- Keep the repository topology and package-manager split consistent with the [owning Agent Note](.agents/notes/implemented/process/2026-08-15-pinned-upstream-and-isolated-yarn-workspace.md).

## HuaAnWork variant (`dsh-plugin-huaanwork`)

- Derived from the retired `dsh-plugin-desktop-beta` tree at M1 (2026-09-19); that directory was deleted on 2026-10-30, so the derivation is historical identity, not a live variant. Identity source of truth: `dsh-plugin-huaanwork/src/product-identity.ts`.
- `dsh-community-market` DSH dependencies are synced and verified through the `huaanwork` channel only: `sync-vendored-runtime.mjs` owns the market manifest in that channel. The market's runtime peers are `0.2.0-rc.2 || 0.2.1-rc.1`: the historical Stable leg is retained by `upstream.json` `marketPeerPolicy.stableHistorical: retain`; the dormant alpha.1 leg is retired.
- Two market upgrade paths are deliberately unbuilt: an inner-network registry carrying the dependency closure, and multi-source keyring / per-source public keys. They require a new ruling because they replace or expand the trust root. See `docs/market-upgrade-paths.md`; keep the fail-closed baseline (zero-dependency + double gate + `--offline` fallback, single canonical source with two-slot pins).
- macOS release acceptance is **"credentials arrive → sign"**. The pipeline is complete and documented in `docs/release-checklist.md`; unsigned intranet artifacts are expected until credentials arrive.
- Root `scripts/*.json` remains the single source for shared fixtures. Runtime/test consumers use `readFileSync`, not imports, to avoid breaking package typechecks.
- Permanent upstream differences: keep `dsh.optionalBundles` in its first list form; keep sandbox Windows ACL failures loud with the diagnostic skill. Do not silently align either with upstream.
- Continue reapplying the directory-bridge patch and using browse host+surface on Windows. The native upstream Windows dialog bypasses the desktop workspace-validation bridge and needs separate review and Windows validation before adoption.
- Market duplicate-install acceptance is UI disabled + underlying `restart-required`/`changed=false` + unchanged profile bytes, not the unreachable `already-installed` result.
