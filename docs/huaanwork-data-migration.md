# 旧版数据迁移说明（HuaAnWork → HuaAnWork Desktop）

新版 HuaAnWork Desktop（基于 DSH）在**首次启动**时会把你已安装的旧版
（Tauri 版 HuaAnWork）的数据自动迁移到新版布局。本文说明迁移的触发条件、
迁移与不迁移的范围、旧数据目录、失败时的表现，以及迁移后需要注意的事。

> 本文面向使用者。实现细节（迁移步骤与失败路由）见
> `dsh-plugin-huaanwork/src/huaanwork-migration/` 与 `src/main.ts` 的钩子注释。

## 1. 迁移什么时候发生

以下三个条件同时成立时，迁移在启动过程中执行**一次**：

1. **首次以新版启动**（本次启动的 DSH 主目录与活动 Profile 就位之后、应用界面加载之前）；
2. **检测到旧版数据**：旧配置目录内存在 `settings.json` / `account.json` /
   `auth-session.json`，或存在旧 DSH 数据树（旧配置目录下的 `dsh/`）；
3. **活动 Profile 内没有迁移标记** `huaanwork-migration.json`。

补充说明：

- 迁移**不会**在以下场景执行：**安全模式**（使用一次性临时环境，不读取也不写入你的数据）；
  从重启菜单显式请求的**恢复模式**。
- 迁移在 Profile 组合之前完成，因此你第一次进入新版界面时看到的就是迁移后的数据。
- 只有旧数据**没有被删除**且标记缺失时才会重跑；正常情况下每个 Profile 只迁移一次。

## 2. 迁移了什么（11 类）

| # | 内容 | 旧位置 | 新位置（Profile = `<主目录>/profiles/<名称>`） |
| --- | --- | --- | --- |
| 1 | 应用设置 | `<旧配置目录>/settings.json` | `<Profile>/huaanwork-settings.json` |
| 2 | 本地账号（用户名与口令散列） | `<旧配置目录>/account.json` | `<Profile>/account.json` |
| 3 | 会话记录（含压缩日志） | `<旧配置目录>/dsh/sessions/` | `<主目录>/sessions/`（中性根会话重铸为新 id） |
| 4 | 项目列表 | `<旧配置目录>/dsh/projects.json` | `<Profile>/projects.json` |
| 5 | 任务列表 | `<旧配置目录>/dsh/tasks.json` | `<Profile>/tasks.json` |
| 6 | 自动化任务 | `<旧配置目录>/dsh/automations.json` | `<Profile>/automations.json` |
| 7 | 自动化运行记录与审计 | `<旧配置目录>/dsh/automations/*.runs.jsonl`、`*.audit.jsonl` | `<Profile>/automations/`（同名） |
| 8 | 局域网智能体配置 | `<旧配置目录>/dsh/agents-enabled.json`、`agents-endpoints.json` | `<Profile>/`（同名） |
| 9 | 技能开关 | `<旧配置目录>/dsh/skill-toggles.json` | `<Profile>/skill-toggles.json` |
| 10 | 用户技能 | `<旧配置目录>/dsh/skills/` | `<Profile>/skills/` |
| 11 | 中性工作区内容 | `<旧配置目录>/dsh/workspace/` | `<Profile>/workspace/` |

旧版的「中性根」会话（固定在旧 `workspace/` 目录上的对话）在新版对应
`<Profile>/workspace/`，路径变了，会话 id 也随之**重新铸**一次；任务与自动化
指向它的引用会同步改写。项目根目录、旧聊天与自动化运行产生的会话保持原样搬运。

## 3. 没有迁移什么（6 项，附理由）

| 内容 | 理由 |
| --- | --- |
| `cordis.yml` | 旧版的插件图（进程组合文件）。新版组合由 Profile 自己管理，旧图直接搬过来会让新版加载错误的插件集合。 |
| `cordis.patch.yml` | 同上，旧版的补丁文件对不上新版组合。 |
| `logs/plugin.log` | 旧进程的日志，不属于用户数据。 |
| `logs/sidecar.log` | 同上。 |
| `auth-session.json` | **有意不迁移**：旧版仅凭该文件存在即视为已登录，等于把「已登录」当文件保存；新版要求重新登录一次（见第 6 节）。 |
| `profiles/huaanwork` | 旧版 Profile 目录（插件清单）。插件安装与来源校验归新版的插件市场，旧清单不可复用；其中装过的**插件包名**会被记录并在首启日志里列出（见第 7 节）。 |

以上各项都会写入迁移标记的「未迁移」清单，首启日志与标记里都能看到，
不会被静默忽略。

## 4. 旧数据目录在哪、会不会被删

旧配置目录（三平台）：

| 平台 | 旧配置目录 | 旧 DSH 数据 |
| --- | --- | --- |
| macOS | `~/Library/Application Support/HuaAnWork/` | 其中 `dsh/` 子目录 |
| Windows | `%APPDATA%\HuaAnWork\` | 其中 `dsh\` 子目录 |
| Linux | `~/.config/HuaAnWork/` | 其中 `dsh/` 子目录 |

新版数据位置：DSH 主目录为 `~/.huaanwork`（Windows 为
`%USERPROFILE%\.huaanwork`），各 Profile 在其下的 `profiles/<名称>`（默认名
`desktop`）。

**迁移不删除、不改写旧目录**：旧文件在迁移前后逐字节一致。确认新版使用正常后，
你可以自行删除旧目录释放空间（迁移标记仍在，不会因此触发重迁）。

## 5. 重要：迁移完成后请停用并卸载旧版（共存分叉警告）

迁移完成后，**旧版仍然可以运行**——但它读写的是同一棵旧数据树。请务必注意：

- 迁移只在新版侧复制了一份快照；**迁移不会重跑**（标记已存在）。
- 你在**旧版**里新产生的会话、项目、自动化**不会**出现在新版中，而且**没有任何提示**；
  反过来，新版的改动也不会回到旧版。
- 因此：**迁移完成后请停用并卸载旧版**，只保留新版。

如何确认自己正在运行的是新版：

- 新版的产品名是 **HuaAnWork**，macOS 安装包/关于框的 **bundle id 为
  `app.huaanwork.desktop`**；旧版的 bundle id 是 `com.huaanwork.desktop`。
  两者的 bundle id 不同，不会互相覆盖安装，可以从「关于」信息里区分。
- 版本号以你安装的发行包为准；旧版既不再收到更新，也不参与新版的恢复窗口与更新检查。

## 6. 需要重新登录一次

- 本地账号本身（用户名与口令散列）已经迁移，**用户名与口令不变**。
- 旧版的登录会话文件 `auth-session.json` **有意不迁移**：旧版只要该文件存在就视为
  已登录，任何能读到它的人都能冒充你；新版要求显式重新登录一次。
- 登录状态按 Profile 独立：新建或切换到另一个 Profile 时，需要在该 Profile 里登录一次。

## 7. 旧版安装的插件需要在新市场重新安装

旧版的插件不在迁移范围内（旧插件图与旧 Profile 清单一并留在旧目录），
需要在新版的「插件市场」重新搜索安装。

迁移会把旧版装过的插件包名列出来（写入迁移标记的「未迁移」清单，并出现在首启
应用日志里）。你也可以自己核对：

1. 打开旧目录下 `dsh/profiles/huaanwork/package.json`（三平台路径见第 4 节；
   例如 macOS：`~/Library/Application Support/HuaAnWork/dsh/profiles/huaanwork/package.json`）；
2. 查看 `dsh.profile.bundles` 数组，其中的字符串就是包名；
3. 在新版插件市场按包名重新安装。

## 8. 迁移失败时会怎样

迁移失败（磁盘已满、权限不足、文件被占用、旧文件损坏等）时：

- **不会**静默跳过，**不会**删除旧数据，也不会带着半份数据继续启动；
- 新版报错并进入**恢复窗口**（恢复助手），界面不会正常打开。

恢复窗口里可以做的事：

- **启动检查点（三槽位）**：回滚到最近的健康配置快照（Profile 与设置文件）；
- **安全模式**：用临时环境启动（不读取你的数据，也不执行迁移），可用于查看诊断；
- **插件管理**、**Profile 切换**、**诊断导出**（把日志导出给维护者）。

注意两点：

- 回滚检查点不会「修好」迁移失败本身的成因；迁移会在下次正常启动时**重跑**，
  直到成功为止（重跑安全，见第 9 节）。
- 若反复失败，请检查旧数据目录与新数据目录的读写权限与磁盘剩余空间，
  或导出诊断交维护者处理。

## 9. 幂等性：不会重复搬，也不会覆盖

- 迁移成功后在活动 Profile 目录写入标记 `huaanwork-migration.json`；
  之后正常启动直接跳过迁移。
- 每一步的规则都是「**目的文件已存在则跳过，绝不覆盖**」，因此：
  - 迁移中途崩溃或断电：下次启动从未完成/缺失的部分继续，已搬好的文件不动；
  - 手动删除标记会触发重迁，但同样只补缺失项，不会覆盖任何已存在的文件。
- 标记中记录了源路径、各类数据的迁移计数、跳过项与未迁移清单，可用于自行核对。

## 10. 多个 Profile 时的行为

- 迁移标记落在**活动 Profile** 内。切换到（或新建）第二个 Profile 时，
  迁移会**再执行一次**：设置、账号、项目/任务/自动化注册表等会在该 Profile 下
  各出现一份（`account.json` 等会同时存在于多个 Profile）。
- 会话日志存放在 DSH 主目录（多个 Profile 共享），普通会话不会重复；
  但每个 Profile 有各自的中性工作区，因此中性根会话会在新 Profile 里
  重铸出该 Profile 自己的一份。
- 已存在的目的文件不会被覆盖：多 Profile 的重复迁移只补齐缺失文件；
  如果你不需要旧数据（例如新 Profile 只是新工作区），忽略迁移结果即可。
