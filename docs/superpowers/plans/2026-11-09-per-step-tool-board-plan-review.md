## 3. 阻断项（实施前必须修正）

### B-1 思考与正文仍未按轮次闭合关联

证据：

- 计划 `:1090-1104` 只在遇到不同 key 的下一块 thinking 时停止；下一轮无 reasoning、直接产生正文时，上一轮思考仍会误显示“已生成”。
- 计划 Task 1 只给 `TurnItem` 的 thinking 变体加 key，assistant 变体没有 key。
- `App.tsx:4767-4773` 的 `thinkingBefore` 只取最近 thinking，不核对 key。
- `App.tsx:4623-4640` 会用该 reasoning 决定当前 assistant 是否显示自己的思考。

最小修正：

1. assistant 也携带并消费 `roundKey`；`hasAssistantTextAfter` 遇到明确属于其他 key 的正文时不得为当前思考收尾。
2. `thinkingBefore` 只关联同 key 思考；未命中时不得回落到异键思考。
3. 明确 `undefined` 的归属规则：混合键场景下，无 key 条目跟随当前轮，只有**明确不同** key 才构成跨轮，避免旧日志全部被误判为异轮。
4. 新增“下一轮无 reasoning、有正文”“当前正文带内联 think、前一轮有 reasoning”“混合 undefined/key”回归测试。

### B-2 `appendToken` 会合并不同 step 的正文

证据：计划 `:950-956` 对相邻 assistant 无条件合并，合并后保留旧条目的 key。无工具 step、max-tokens 或 steer/inject 续步都可能产生相邻 assistant。

最小修正：只在 `last.roundKey === roundKey`（含双方皆 undefined）时合并；不同 key 新建 assistant。新增“无工具轮次之间相邻正文不合并”测试。

上文 §1–§8 复核的是修订前的计划。当前计划已经吸收 B-1、B-2 与 I-1–I-6。本节只记录修订后仍然挡住 Task 9 实时验收的一项。静态核对，未实跑 CDP。

### T9-1 同拍 `requestSubmit()` 提交的是空草稿

严重度：重要。影响 A1、A2、A4、A5、A8。A3、A6、A7、A9 不走这条发送。

`send()` 读的是 React 状态 `draft`（`App.tsx:2641`），`text` 为空就在 `:2644` 直接返回。发送按钮在 `draft` 为空时禁用（`App.tsx:3842`）。计划 Task 9 的 `sendExpression`（`2026-11-09-per-step-tool-board.md:1656-1665`）在同一次调用里改输入框、派发 `input`，然后立刻 `form.requestSubmit()`。`requestSubmit()` 不看按钮禁用状态。`input` 触发的 `setDraft` 还没写进这次提交所读的 `draft` 时，`send()` 收到空文本并返回，随后等待用户气泡的步骤超时。`--action=stop` 也先走同一个 `sendExpression`，所以停止验收同样发不出去。

仓库里已经跑通的验收脚本会等 React 把草稿写入，再点可点击的发送按钮（`dsh-plugin-huaanwork/scripts/huaanwork-subagent-run-windows-acceptance.mjs:481-492`）：设置值、派发 `input`、等待 80 毫秒、确认 `button.send[aria-label="发送"]` 存在且未禁用，然后 `click()`。

### 修法

只改计划里的 `sendExpression`，让 `--action=send` 和 `--action=stop` 的首发都走这条路径：

1. 用原生 setter 写入 `textarea`，再派发 `bubbles: true` 的 `input`。
2. 等待约 80 毫秒，让 `onChange` 写回 `draft`。
3. 查找 `.composer button.send[aria-label="发送"]`。按钮不存在或仍禁用时返回失败，由外层重试，直到按钮可点。
4. 对按钮 `click()`。删除同拍 `form.requestSubmit()`。
5. 停止验收保持现有顺序：先按上面的方式把提示发出去，再等待 `.send.stop` 出现并点击。停止按钮本身不用改。
