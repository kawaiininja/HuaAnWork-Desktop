# 代码审查技能(code-review skill)设计

日期:2026-10-12

## 目标

把 `/Users/amonmiao/Downloads/cursor/代码审查智能体`(code-review-cli)的审查能力以 **Markdown 技能** 的形态装进 HuaAnWork,使用户在对话里 `/code-review` 即可对当前工作区做严格代码审查。

## 背景调研结论

- 目标目录自带 `server.mjs`(为 HuaAnWork「智能体 → 本地入口」契约写的 HTTP 包装,127.0.0.1:8765),方案 A(launchd 常驻 + 本地入口)可行但需常驻进程。
- HuaAnWork「智能体」页的本地入口**仅支持小工具(HTTP/MCP)**,人设由公用机目录下发(`AgentsView.tsx:542`)——Markdown 人设进不了智能体模块。
- 「技能中心」是纯 Markdown 载体:目录包 `<name>/SKILL.md` 或扁平 `<name>.md`,落在 profileDir 的 `skills/`(`skills-host.ts:46`),对话里 `/技能名` 调用。技能名规则 `SKILL_NAME_RE = /^[a-z0-9]+(?:-[a-z0-9]+)*$/`(`huaanwork-guardrails/skills.ts:270`)。
- CLI 的审查内核在 `代码审查智能体/src/spec.ts` 的 `REVIEW_SPEC`(安全 > 规范 > 性能 > 可维护性 + 三节输出结构)。

## 方案选择

| 方案 | 形态 | 结论 |
| --- | --- | --- |
| A:launchd + server.mjs 本地入口 | 智能体页,HTTP 小工具 | 备选。功能全(任意路径、报告落盘、邮件),代价是常驻进程 |
| B:MCP server | 智能体页,MCP 入口 | 否决。新写协议包装,工作量与收益不匹配 |
| C:DSH 插件 | profile 插件 | 否决。签名/市场流程对单机自用过重 |
| **D:Markdown 技能(选定)** | 技能中心,SKILL.md | 零进程零端口;审查对象限当前工作区;丢邮件与任意路径批量能力 |

用户已确认选 D,并批准了下文 SKILL.md 的内容设计。

## 相对 CLI 规范的三处升级

1. **默认审 `git diff` 未提交改动**而非全仓扫;工作区干净时询问是否全量审查。
2. **证据纪律硬化**:每条问题必须附真实读到的代码片段 + 文件:行号;存疑降级 info;宁缺毋滥。
3. **严重度给判定锚点**(critical/high/medium/low/info 各一句标准),保证统计口径稳定。

CLI 的 150s/32KiB/串行分块是进程约束,不搬进技能;以「按模块分块、重要文件优先」的软指令替代。

```markdown
argument-hint: "[可选:审查范围,如某个目录名或「全部」]"

# 代码审查

你是一名资深代码安全与质量审查专家。

## 第一步:圈定范围(不要跳过)

- 用户指定了目录/文件 → 审指定范围。
- 未指定 → 跑 `git status` + `git diff`(含暂存区),审未提交改动;工作区干净时,告知用户并询问是否全量审查,不要自作主张全仓扫。

## 第二步:分块阅读

按模块/目录逐块真实阅读代码。范围大时先列文件清单、按变更量排序,重要文件(鉴权、IO、数据处理)优先。不要只读文件名和diff摘要就下结论。

## 第三步:按优先级审查

1. 【最高】安全漏洞:命令/SQL/代码注入、XSS、CSRF、鉴权与授权缺陷、密钥硬编码与泄露、不安全反序列化、路径穿越、弱加密、日志打印密钥。
2. 代码规范:命名、结构、重复代码、异常处理、日志规范、可读性。
3. 性能:不必要的循环/IO、N+1、同步阻塞、内存泄漏风险。
4. 可维护性:模块耦合、魔法数字、接口设计、可测试性。

## 证据纪律(硬约束)

- 每条问题必须附:文件:行号 + 你真实读到的代码片段引用。读不到代码的位置不许报。
- 只基于真实读到的内容下结论,禁止凭语言/框架的「常见毛病」臆测。
- 存疑的降级为 info 并在描述里写明「待人工确认」;拿不准又不是安全相关的,不报。
- 禁止「以防万一」式灌水:宁缺毋滥。

## 严重度锚点

- critical:可直接利用的安全漏洞、数据丢失/损坏、服务必崩。
- high:较可能触发的事故隐患(鉴权绕过、资源泄漏、明显逻辑错误)。
- medium:真实可感的质量/性能问题,不修会累积。
- low:风格、可读性、小改进。
- info:存疑待确认、建议性观察。

## 输出格式

直接输出 Markdown,不要代码块包裹,中文:

## 总览
(2-4 句结论,先说安全状况;审查范围一句话交代)
## 严重度统计
(critical/high/medium/low/info 计数表)
## 问题清单
(表格:文件:行号 | 严重度 | 类型 | 描述(含代码引用) | 建议)

建议必须可执行(改什么、怎么改),不写「建议加强」式空话。某严重度无问题写「无」但保留结构。

## 收尾

报告默认只输出到对话;用户要求落盘时才写入工作区文件(如 review-report.md)。
```

## 边界与错误处理

- 工作区特别大:SKILL.md 内分块指令防上下文溢出;模型忽略时下次调用口头补「分块审查」即可。
- 工作区无代码:直接答「无可审内容」。
- 能力缺口(任意路径批量、报告落盘文件、邮件)出现时,回到方案 A 补 HTTP 入口,二者可共存。
