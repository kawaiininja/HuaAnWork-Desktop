# 自动化结果预览、运行记录删除与停止

- 日期：2026-10-21
- 状态：终审通过（2026-10-21，见规格评审 §七）。实施计划 `docs/superpowers/plans/2026-10-21-automation-result-preview.md` 的评审见 `docs/superpowers/plans/2026-10-21-automation-result-preview-review.md`。N2-O1 仍是窄窗口：`stopAutomation` 返回前的等待关不掉它。N2-O2 仍只是锁顺序措辞，不改行为。
- 范围：HuaAnWork 高级模式里的自动化运行对话、右侧「预览」、自动化页的运行记录与停止。只改 `dsh-plugin-huaanwork`。不改 `deepseek-harness/`，不改 Stable/Beta 源码。

## 1. 目标

| 编号 | 用户要求 | 本轮行为 |
| --- | --- | --- |
| R1 | 自动化任务的 JSON 结果不要直接铺在对话里 | 整段助手回复是 JSON 对象或数组时，收起原文，换成「结果.md」和「结果.html」 |
| R2 | 点附件后在右侧「预览」查看，并能下载 | 点哪一份就预览哪一份。预览打开时提供下载，只下载当前这一份到系统下载目录 |
| R3 | 运行记录可以删掉单条 | 「运行记录」每一行有删除。确认后删掉该条记录和它的会话目录 |
| R4 | 「清理历史运行会话」少留一些会话目录 | 每个任务保留最近 20 条运行的会话目录。运行记录本身仍最多 50 条 |
| R5 | 运行中的自动化任务可以停止 | 任务行和运行对话都能停止已经开始的这一轮，并记为「已取消」。同任务尚未开始的排队轮一并丢掉且不写记录。到期档位按第 8 节消费，避免同一档立刻再跑 |

## 2. 不在本轮

- 不把「结果.md」「结果.html」写进项目目录。
- 不改运行记录文件的 50 条上限，不改看板和任务行展开历史里的原文展示。
- 脚本任务没有运行对话，不为它们生成附件。停止和删除仍适用于脚本运行。
- 不给任务行里展开的运行历史另放删除按钮。那边的列表在删除成功后随刷新更新。
- 不给纯排队、界面上还显示「立即运行」的轮次单独做停止按钮。
- 下载文件名不带时间戳。重复下载覆盖下载目录里的同名文件。
- 不增加「把两次运行的附件打包下载」。
- 不改 Stable、Beta、`dsh-desktop-next`。

## 4. JSON 附件

### 4.1 何时折叠

只处理带 `automationId` 的运行对话。两处调用同一个纯函数：

1. 收到 `automation/run-end` 时，对该会话标签里的当前条目折叠。
2. 重启后懒加载会话记录、`historyToChatItems` 完成之后、追加结果脚注之前。

判断用对话里的助手正文，不用运行记录里被截断的 `output`。把所有 `kind: "assistant"` 的 `text` 按顺序拼起来，去掉闭合的 `<think>…</think>`，再丢掉未闭合 `<think>` 及其后的文本，然后去掉首尾空白。`JSON.parse` 的结果是对象或数组（含空对象、空数组）才折叠。`null`、数字、字符串、布尔，以及拼上说明文字后不再是合法 JSON 的正文，保持原样。

失败、超时、已取消的运行同样按这条规则折叠。生成过程抛错时，助手原文保留，结果脚注照常追加。

### 4.2 对话里留下什么

折叠时删掉全部助手气泡，在第一条被删助手气泡的位置插入一条附件消息。思考、工具、提问、待办和已有脚注留在原处。随后追加的结果脚注仍在末尾。

附件消息固定两份，名字为 `结果.md` 和 `结果.html`。内容来自同一棵块树：先把 JSON 转成块，再分别渲染成 Markdown 和完整 HTML。不把渲染结果写入磁盘。

### 4.3 块怎么对应 Markdown

- 顶层对象的每个字段为一节。字段名是二级标题，值写在标题下面。嵌套对象同样按字段展开，标题级别加一，最高到四级；更深的字段名用加粗段落。
- 元素都是对象的数组写成表格。列按字段第一次出现的顺序，跳过 `__proto__`。格子里的对象或数组写成一行 `JSON.stringify`。
- 表格单元格里的 `|` 写成 `\|`，换行写成空格。下载的 Markdown 被其他渲染器打开时，单元格不会拆开表格。
- 其他数组写成列表。
- 字符串按原文分段，不把字符串里的 `#`、`|`、反引号再解释成 Markdown。
- 数字、布尔和 `null` 写成文本。
- `{}` 的正文是「（空对象）」，`[]` 的正文是「（空数组）」。

HTML 按块树渲染，不把 Markdown 原文再解析一遍。写入 HTML 的文字全部转义。表格单元格使用与 Markdown 相同的压平文本，再做 HTML 转义。

## 5. 预览与下载

预览选择记在对应的对话标签上。点「结果.md」显示 Markdown 原文，点「结果.html」显示渲染后的页面。点击后留在当前对话，右侧切到「预览」；右侧栏收起时展开。换到别的对话再回来，显示该对话上次点开的那一份。没点过时仍是现在的空占位。

HTML 放在 `sandbox=""` 的 iframe 里，用完整文档作为 `srcdoc`。文档包含文档类型、`utf-8`、标题「结果」，不含脚本和外链资源。

已经打开一份附件时，预览标题旁显示「下载」。它只下载当前这一份。渲染进程用该附件的文件名发起下载。主窗口会话在 `electron-shell-generation.ts` 里处理 `will-download`：建议文件名是 `结果.md` 或 `结果.html` 时，把保存路径设为 `app.getPath('downloads')` 下的同名文件，不弹出保存框。其他下载不接管。该文件已是 beta 与 huaanwork 的声明差异，这次不新增变体白名单条目。

重复下载覆盖下载目录里的同名文件。不写入项目目录。空占位不显示下载按钮。文件名是否属于这两份附件、以及对应的下载目录路径，抽成可单测的纯函数。

## 6. 删除单条运行记录

「运行记录」每一行增加「删除」。先确认，文案说明对应的会话目录会一并删除。确认后调用新的 `automation.deleteRun`，参数为任务 id 和 `runId`。

宿主在该任务的运行记录锁里删掉这一行。若 `sessionId` 存在，先对该 id 调用 `releaseSessionRuntime`，再按 `pruneAutomationSessions` 的同一套会话根目录查找并删除该目录。记录删除成功后，即使目录删除失败，列表里也不再出现这一条，界面报告目录未能删除。目录不存在视为已经删掉。

执行中的轮次要到结束才写入运行记录，正常界面删不到它。`deleteRun` 若发现该 `runId` 仍在第 8 节的在途表里，拒绝删除，界面保持原列表并说明运行中的记录不能删除。

回写 `lastRunAt` / `lastStatus` 放在注册表锁内。进入这把锁之后重新读取运行记录文件，用这份新内容计算基准，不用删行当时留下的快照。持有注册表锁期间不再获取运行记录锁：`finishAutomation` 先拿运行记录锁、再等注册表锁，反过来嵌套会死锁。锁内重新读取任务。读到的 `lastStatus` 已是 `running` 时，不改这两个字段。否则，在新读到的记录里跳过 `status: "missed"`，用 `startedAt` 最新的一条真实运行回写：`ok` 写 `ok`，其他终态写 `error`，`lastRunAt` 取该条的 `endedAt`。没有真实运行剩下时去掉这两个字段，任务行显示「从未运行」。`missed` 不回写成一次执行。删行之后、回写之前若已有新的真实运行落盘，回写必须看见它，不得用旧快照盖掉它的注册表项。

客户端在成功后刷新运行记录。若某个运行对话标签的 `sessionId` 等于被删记录，关闭该标签。默认对话标签不因这次删除被关掉。被关的是当前标签时，改选其余标签里紧挨它的一个。运行记录详情若正打开这一条，关闭详情回到列表。

## 7. 清理会话改为保留 20 条

新增与 `RUNS_LIMIT` 分开的常量，值为 20。`pruneAutomationSessions` 对每个任务只把最近 20 条运行的 `sessionId` 放进保留集，并继续保留调用方传入的进行中会话。只删除自动化会话目录，不改运行记录文件。

确认文案改为说明将删除每个任务最近 20 条运行之外的会话目录。`automation.pruneSessions` 的注释与 `projects.ts` 里的说明改成 20。第 21 条及更早的运行记录还在，点开时可以没有完整会话。

## 8. 停止运行中的任务

宿主维持一张按 `runId` 索引的在途表，供停止、删除拒绝和档位消费共用。每条至少有任务 id、`runId`、触发方式（`schedule`、`catchup` 或 `manual`）、阶段（`queued` 或 `started`）和取消请求标记。真正入队时写入 `queued`：`dispatchEnqueue` 在调用 `enqueueAgentAutomation` 或 `enqueueScriptAutomation` 的同步段里，使用调用方已传入的 `runId`，没有传入才生成，并立刻写入在途表。这发生在跨根判断放弃入队之后，所以未入队的调用不留条目。`runBound` 只使用这份已经确定的 `runId`，不再生成另一个。发出 `automation/run-start` 时改为 `started`。记录落盘之后，或排队轮的档位已经按下面的规则消费一次之后，删除条目。

新增 `automation.stop`，参数为任务 id。它处理该任务在途表中的全部条目：

- 没有条目：返回未停止。界面刷新后按钮恢复为「立即运行」。
- `queued`：在同步段里声明这一条由本次停止消费档位，并标记取消。随后按下面的规则消费档位，且该 `runId` 只消费一次。执行体醒来时若看到取消标记，在同一段同步代码里返回：不把阶段改成 `started`，不发 `run-start`，不写运行记录，也不再消费档位。
- `started`：标记取消。定时对话调用 `cancelAutomationSession`。脚本结束对应子进程。agent 尚未建成时取消调用是空操作，标记仍然有效。这一轮仍走 `finishAutomation` 落盘，状态写 `cancelled`，即使用户停止时模型回合后来自己跑完，也不写 `ok`。脚本这次结束不记为超时。产出用已经收集到的文本；什么都没有时正文为「已停止」。注册表 `lastStatus` 写 `error`。一次性任务沿用收尾里的停用。同一 `runId` 只写一条记录。
- 停止到达时该 `runId` 的记录已经落盘：不再写第二条，返回未停止。

执行体从排队里醒来后的第一段是同步代码，中间不能 `await`，实现处用注释钉住这段不变量：要么看见取消标记并返回，要么把阶段改成 `started` 并发出 `automation/run-start`。`stop` 因此不能插在「还是 queued」和「已经 started」之间。只有同步声明时阶段仍是 `queued`、且尚未声明过消费的那一次停止消费档位。这次声明在任何 `await` 之前写入条目，后到的停止看见已声明就不再消费。声明之后的注册表写入可以异步，但执行体不再写第二遍。阶段已经是 `started` 的条目只走上面的已开始路径。

档位消费只针对被跳过的 `queued` 轮，按下面的顺序只取一条：

1. 日程种类是 `once`：停用任务并去掉 `nextRunAt`，与一次已经开始的一次性任务结束后的注册表结果一致。不再推进别的档。
2. 触发方式是 `schedule`：用跳过时刻调用与 `markAutomation` 进入 `running` 时相同的 `nextFireAfter`，推进 `nextRunAt`。这一档因此不会在宽限内被下一拍再次入队。
3. 触发方式是 `catchup`：入队前调度器已经推进过 `nextRunAt`，这里不再推进。
4. 触发方式是 `manual`：不改 `nextRunAt`。

`runningAutomationIds` 只覆盖 `started`。任务行和运行对话的「停止」只在这时出现，调用 `automation.stop`。纯排队时任务行仍是「立即运行」，没有单独的停止按钮。同任务若同时有一条 `started` 和一条 `queued`，一次停止两处都处理。运行对话的停止不走普通用户回合的停止。停止后的对话文本仍按第 4 节折叠。

任务行的「上次」仍由 `lastRunLabel` 读取注册表的时刻和 `lastStatus`。仅当该任务已加载的运行记录里 `startedAt` 最新的一条是 `cancelled` 时，状态词显示「已取消」。不因这条约把 `missed` 显示成「已错过」，也不把 `timeout` 从「失败」改成「超时」。

## 9. 代码与测试

纯函数放在 `dsh-plugin-huaanwork/src/client-huaanwork/logic/`：JSON 判断、块树、Markdown、HTML、对话折叠，以及下载文件名到保存路径的判定。`ChatItem` 增加附件种类。`App.tsx` 在运行结束和回填两处调用同一个折叠函数，并持有每个对话的预览选择。附件按钮、预览和下载的样式改 `styles.css` 后运行 `yarn gen:styles`，让 `styles.generated.ts` 与源文件一致。

删除、保留条数和停止放在 `huaanwork-host` 的现有存储与运行模块，并在 `routes.ts` 增加 `automation.deleteRun` 与 `automation.stop`。下载接管加在 `electron-shell-generation.ts` 的主窗口会话上。

单测至少覆盖：

- 对象、对象数组、普通数组、嵌套对象转成第 4.3 节的 Markdown，HTML 含转义后的正文。表格单元格中的 `|` 和换行按第 4.3 节压平。
- `null`、数字、字符串、前后带说明的 JSON、空文本不折叠。
- 折叠后工具行和完成脚注仍在，助手气泡被两个附件替换；生成抛错时原文不动。运行结束和重启回填调用的是同一个函数。
- 删除一条后 jsonl 少该行，对应会话目录消失，且目录删除前调用了 `releaseSessionRuntime`。在途表中的 `runId` 被拒绝。删掉最新一条后 `lastRunAt` 回退；剩下的最新一条是 `missed` 时跳过它。删光真实运行后两个字段不存在。锁内读到 `running` 时不回写。回写读的是注册表锁内重新读取的运行记录；删行后新落盘的真实运行不会被删行时的旧快照盖掉。测试不把运行记录锁套进注册表锁。
- `pruneAutomationSessions` 保留最近 20 条的会话和进行中会话，第 21 条的目录被删除，运行记录文件不变。
- 停止已开始的定时对话和脚本各写一条 `cancelled`。取消请求早于 agent 建成时，落盘状态仍是 `cancelled`。记录已经落盘后再停止，不追加第二条。
- 跳过 `schedule` 排队轮会推进一次 `nextRunAt`，跳过 `catchup` 不再推进，跳过 `manual` 不改 `nextRunAt`，跳过尚未开始的 `once` 会停用任务并去掉 `nextRunAt`。这些排队轮都不写运行记录。同一次排队轮不消费第二遍。调度入队之后、执行体醒来之前，在途表里已有 `runId`；调用方传入的 `runId` 不变；跨根放弃入队时表中没有条目。
- 建议文件名为 `结果.md` 或 `结果.html` 时保存路径在下载目录下；其他文件名不接管。

## 10. 验收

1. 一次产出为 JSON 对象的定时对话结束后，对话里不再显示那段 JSON，而能看到「结果.md」和「结果.html」。工具行和「自动化运行完成」仍在。
2. 点「结果.md」右侧显示 Markdown 原文；点「结果.html」显示渲染页面。下载直接进入系统下载目录的同名文件，不弹出保存框。再下载一次会覆盖该文件。项目目录不出现这两个文件。
3. 产出为普通句子时，回复气泡保持原样，没有附件。
4. 重启应用后再打开该运行标签，JSON 产出仍显示为两个附件。
5. 在「运行记录」删除一条已结束记录后，该行消失，其会话目录消失。正在打开的该条详情回到列表。运行中的记录删不掉。
6. 清理历史运行会话后，每个任务只留下最近 20 条运行的会话目录。更早的运行记录还在列表里。
7. 运行中点「停止」后，这一轮变为「已取消」，任务行不再停在「运行中」。同任务尚未开始的排队轮不新增记录。被停掉的到期档不会在宽限内自己再跑起来。
