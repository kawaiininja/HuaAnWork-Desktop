# HuaAnWork 会话分流、思考面板与长任务规格

- 日期：2026-10-19
- 状态：草案，取代 2026-10-18 的编排规格。方向按 2026-10-19 评审收敛，具体默认值随本文一起待批准。
- 取代：`docs/superpowers/specs/2026-10-18-conversation-orchestration-design.md`。那一版的 Run 账本、动作指纹、沙箱收窄和 45 条验收不进入本轮。
- 范围：HuaAnWork 桌面高级模式的交互式对话。复用现有 DSH 模型、工具、权限和沙箱。不改 `deepseek-harness/`，不改 Stable/Beta 源码。
- 基线：HuaAnWork 声明运行时 `0.2.1-rc.1`。行号以符号名为准，源码存在不等于已经在真机跑过。

## 1. 目标

| 编号 | 用户要求 | 本轮产品行为 |
| --- | --- | --- |
| R1 | 先理解意图。简单请求直接调工具。复杂请求先拆解、定计划、再按计划执行，做完后交回结果 | 一次分流。简单请求不进入计划模式。复杂请求用官方计划模式写出计划，由华安对话展示并按现有护栏决定是否先确认。待办只展示进度。文件和测试是否真的存在由程序核对。目标续轮只在发送解耦之后启用 |
| R2 | 在对话里看见模型的思考过程，中文更易读 | 每个助手回合在正文上方放一块可折叠的「思考」面板，流式显示模型自己的 reasoning。系统提示要求思考用简体中文。不翻译，不打开官方轨迹页 |
| R3 | 复杂任务时间长时，不要因为连接超时或进程卡住把任务弄丢 | 发送在受理后返回，不再等到会话空闲。界面分清「正在思考」「工具执行中」「已多久没有新结果」。可以取消当前回合。Host 无响应时可以结束进程。长输出先裁剪，长会话再压缩 |

「做完」指结果核对：用户要求的文件或报告能打开，约定要跑的检查已经有一次工具退出结果，失败时说明缺什么。本轮不逐步证明执行没有偏离计划原文。开放式写作说明哪些项可以自动查、其余等用户看。模型自称完成、`todo_write` 被勾掉、会话回到 idle，三者都不能单独当成成功。

## 2. 不在本轮

- 不新建 Run Coordinator、动作账本、工作区指纹、只读沙箱来回切换、崩溃后续跑的幂等对账。这些留在被取代的 2026-10-18 规格里，本轮不实施。
- 不启用 `jobs`、`tool-jobs`、`workflow-ptc`、`tool-workflow`、`tool-ralph`。
- 不启用官方 `web`、`web-search-deepseek`、`tool-web`、`hmr`，不恢复官方 `llm-deepseek` 行。
- 不启用官方 `subagent` / `subagent_fork`、`tool-schedule`、官方 `tool-skill`、`present`。
- 不启用任何官方 `ui-*` 对话插件，包括 `ui-plan`、`ui-goal`、`ui-trajectory`、`ui-user-questions`。它们注入已被换掉的对话壳，打开后高级模式窗口起不来。
- 不承诺关机、休眠或退出之后继续计算。
- 不把思考过程复制到会话日志以外的新账本，也不提供单独导出。

## 4. 总顺序

实施按这个顺序。后面的步骤依赖前面的行为已经可用。

1. 思考面板。只读现有 reasoning，不动护栏锁，可与后面几步并行。
2. 发送解耦：受理后返回，界面保持「仍在执行」，取消当前回合。
3. 提问服务接到华安自己的回答框。
4. 分流和计划模式。复杂请求才进入计划模式，计划卡在华安对话里。
5. 待办只做进度。产物核对只覆盖文件存在、可打开和已约定的检查。
6. 工具结果裁剪，然后是长会话压缩。
7. 目标续轮。小的轮次上限，界面写明这是自动续跑。

宣布本功能完成，要求 1 到 6 的验收通过。第 7 步单独验收，不作为前六步的阻塞项。

## 5. R1 意图、计划与结果

### 5.1 分流

每个用户请求先得到一次分流，四选一：

| 模式 | 条件 | 行为 |
| --- | --- | --- |
| answer | 不用操作环境就能回答 | 直接回答。不进入计划模式，不调工具 |
| direct | 目标清楚，一次有界操作或短的只读查询 | 立刻走现有工具和权限。不展示计划卡 |
| planned | 多个依赖步骤、多份产物、先查再决定、或用户明确要求先定计划 | 进入计划模式，写出计划，展示后再执行 |
| clarify | 缺了会做错或越权的输入，例如收件人、目标目录 | 提一个可回答的问题并等待。不猜 |

不用提示词长度或预估秒数判断复杂度。删除文件这类短请求仍然走现有审批。显式 `@` 和 `/skill` 保持现在的路由，分流器不把它们改成别的探索。

分流和第一个动作放在同一次模型生成里，不为简单请求再前置一轮分类调用。这一轮看到的工具，是当前会话本来就有的工具，再加上华安新注册的两个控制工具 `propose_plan` 和 `request_input`。这两个名字在 `0.2.1-rc.1` 里不存在，由华安注册，不改用官方的 `exit_plan_mode` 或 `ask_user_question` 充当分流信号。普通工具保持可见，不按这一句话临时撤掉。它们要同时过两道已有的名字门：加入 `present-as` 的 `ALLOWED_TOOLS`，并加入 `model.ts` 的 `isRegisteredToolName`。后者漏掉时，`parseSseToolCalls` 会把这次调用静默丢掉，回合变成一段正文，分流不会发生。它们由华安消费：不产生文件或命令副作用，不进入待办，也不走 `guard_mode` 的逐次询问。

两个工具的参数只接受下列字段，多出来的字段视为无法解析：

| 工具 | 参数 |
| --- | --- |
| `propose_plan` | `objective`：必填、非空字符串，一句话写出理解到的目标。不放计划正文。进入计划模式后，计划仍由模型通过 `exit_plan_mode` 另写 |
| `request_input` | `question`：必填、非空字符串，只问一个问题 |

| 模型在这一次响应里做的事 | 判定 |
| --- | --- |
| 只输出正文，不调用工具 | answer |
| 调用 `request_input` | clarify。问题文本是 `question`。用户提交后，答案作为这次工具的结果回到同一回合，模型接着做。这不是一条新的用户消息，也不再走一次分流。用户取消则工具失败，回合停止，不猜 |
| 调用 `propose_plan` | planned。宿主接着用 `ctx.planMode` 进入计划模式，不使用 `/plan` |
| 调用其他工具 | direct。该调用仍先过现有 policy，再执行 |
| 同一次响应里既有控制工具，又有普通工具 | 以控制工具为准，普通工具不执行 |

控制工具的参数无法解析时，只把这一次响应交回模型重修一次，不重放已经执行的工具。再失败就告诉用户「没能理解这个请求」，并结束这一回合。

第 4 步落地之前，发送没有分流：思考面板和发送解耦按第 4 节先做的步骤单独生效，请求仍直接进入现有 agent。

direct 做到一半发现还要好几步时，可以升级为 planned。已经发生的工具调用保留，不从头重做。

### 5.2 计划模式

在宿主平面重新启用 `@deepseek-ai/dsh-plan-mode`。不启用 `ui-plan`。计划的 Markdown 由华安对话里的计划卡显示，放在该回合的工具行之前。

计划模式只加在已经判成 planned 的请求上。answer 和 direct 不进入计划模式。进入和退出都调用 `ctx.planMode`。华安斜杠只解析技能，`/plan` 与 `/plan off` 到不了官方命令服务，不能当作入口或逃生口。

官方计划模式不关闭工具。计划卡上写一句固定说明：「计划确认前，模型仍可能读取工作区；写入和命令继续走现有权限。」本轮不额外把会话切到只读沙箱。

模型写完计划后调用官方 `exit_plan_mode`。这个工具依赖第 6 节的提问服务。提问服务还没接上时，不启用计划模式。

计划卡按现有 `guard_mode` 决定要不要先点确认：

| 档位 | 行为 |
| --- | --- |
| ask | 先确认计划。确认后，原本要逐次询问的工具调用仍然逐次询问 |
| smart | 计划只含读取和普通命令时，展示后执行。任一步落在现有会询问的集合里（高危命令、`git_push`、脏树 `git_checkout`、附加的 host/MCP 工具，或外发、删除）时，先确认计划 |
| full | 展示后执行。目标、收件人、写入范围变化时仍要再确认 |

`exit_plan_mode` 会发起一次 `plan-review` 并等到回答。需要确认时，第 6 节把这次评审画出来，必须由用户点击，点击才是提交给官方工具的回答。展示后执行时，回答者在场，计划卡先出现，并写明「按当前护栏自动继续」。回答者随即提交同意，不等待点击。这不是补记一次用户点击，也不替代工具级审批。不用在工具仍在等待时单独把 `ctx.planMode` 设为退出，否则这次 `exit_plan_mode` 会停住。回答者没有接上、而这一档又需要确认时，停在等待，不自动提交同意。

对话里始终有「退出计划模式」。它先把尚未回答的 `plan-review` 作废，让等待中的 `exit_plan_mode` 得到拒绝结算，再把 `ctx.planMode` 设为退出。不执行计划里尚未发生的写入和命令。评审卡没有弹出时，用户仍能用这个按钮离开计划模式。

确认计划不等于批准被 policy 拒绝的调用。

### 5.3 进度与核对

在宿主平面重新启用 `@deepseek-ai/dsh-tool-todo`，配置 `allowParallelInProgress: false`。华安把列表画在计划卡下面或当前回合里，状态用中文：待做、进行中、已勾选。

已勾选只表示模型更新了清单。回合结束时，若用户要求的是文件或报告，程序检查路径是否出现在工作区目录树里（列出深度 6）。这是存在性核对，不打开文件句柄。若用户要求跑测试或指定命令，只读取这一回合里已经返回的对应工具结果，以其退出结果为准。程序不另起一条命令重跑。没有对应结果，就列为缺项。对不上就在结果里列出缺项，不把回合标成已完成。

开放式写作不假装有客观证明。结果里写明已经检查的格式或篇幅，以及需要用户自己看的部分。

### 5.4 目标续轮

发送解耦（第 7.1 节）通过之后，才在宿主平面启用 `@deepseek-ai/dsh-tool-goal`。`goal` 服务和 `goal-round-driver` 保持现状，不另写续跑器。

默认一轮目标最多自动续 4 轮。界面在续轮开始时显示「正在按目标继续，第 n/4 轮，这还不是验收结果」。模型调用完成目标，或轮次用尽，或用户取消，就停止。续轮不绕过权限，也不把待办勾选当成完成。

达到上限后停下来，列出尚未核对的项，请用户决定是否再继续。不自动新开一轮目标来绕过上限。

## 6. 提问

重新启用 `user-questions` 服务。不启用 `ui-user-questions`。

华安注册自己的回答者，复用现在的审批卡和澄清输入。问题出现在对应对话里，有明确的提交和取消。没有回答者时不得静默放行去执行写入或外部操作；向用户显示「这个问题还没有人接到」，并停在等待。

计划评审使用官方的 `plan-review` 意图，华安把计划正文和「按这个计划执行 / 继续改计划」画出来。选项的值与官方提问服务一致，避免计划模式认不出批准。

过期或已经结束的提问不能沿用上一次的批准。

## 7. R3 长任务

### 7.1 受理与状态

`sendToAgent` 在消息交给 agent 之后立即返回已受理，不再 `await whenIdle`。原 HTTP 连接断开不取消已经收下的回合。

对话区在回合未结束时显示三条里当前成立的一条：

- 「正在思考」：本回合已有 reasoning 流，还没有新的工具结果。
- 「正在执行工具」：当前有未结束的工具卡，并写出工具名。
- 「已 N 秒没有新结果」：没有新的思考增量、正文增量或工具结果。满 5 分钟时改成醒目的提示，并保留取消按钮。

这三句不使用百分比。心跳或 reasoning 的 token 只说明还活着，不增加完成度。

### 7.2 取消与 Host

取消只作用于当前会话及其已经登记的子代理，不调用「取消所有其他 agent」。取消表示停止继续调度并尽量终止当前命令，不自动回滚已经写过的文件或已经发出的请求。

Electron 主进程对独立 Host 做短周期探活，使用一条独立的短超时 IPC，要求 Host 主事件循环在 2 秒内应答。进程还在、端口还开着，或 stderr 仍有输出，都不算应答。不复用 120 秒的 Host RPC 期限，也不用另一条空闲线程代发心跳。连续约 15 秒没有应答时，界面显示「执行进程无响应」，并停止派发新的用户请求。连续约 60 秒仍无应答且该 Host 上有未结束回合时，提供结束进程的操作。确认前写明将终止的未结束会话数量。没有未结束回合时只提示，不杀进程。

结束进程会停下该 Host 上的全部未结束会话，不只是当前标签。结束之后，界面保留各会话最后一条已知状态，并说明结果可能不完整。本轮不自动重启后续跑。

`DSH_DESKTOP_ISOLATED_HOST=0` 的同进程模式继续只作为开发路径。本轮不在高级模式启动时拒绝它，也不宣称这种模式下有进程外监督。

### 7.3 上下文

在宿主平面重新启用工具结果裁剪（官方 `tool-result-pruner` 那一行）。超长工具输出保留头部和尾部，并标明已截断。

长会话再启用 `compaction-basic`。压缩是后台模型调用，它的正文和思考都不得进入用户对话的思考面板或助手气泡。压缩后的回合若丢失了核对所需的原文，结果里说明「更早的工具输出已被压缩」，需要时让用户重跑该检查。

不因为压缩或续轮去修改 600 秒的模型请求上限，也不打开后台任务。

## 8. R2 思考面板

### 8.1 数据

一个助手回合一块面板。内容只来自两处，按这个优先顺序，同一段文字只显示一次：

1. 模型流的 reasoning。`mapTokens` 在 `purpose === undefined` 时，把 `reasoning-delta` 发到对应会话。块结束时发一次完整文本，供断线后补齐。辅助模型调用不发。
2. 正文里的 `<think>` / `<thinking>` 块。现有 `stripThinking` 继续从助手气泡删掉这些标签。本回合的 reasoning 流只要产生过非空文本，就整段不使用第 2 路。只有 reasoning 为空时，才把标签内文字送进思考面板。

系统提示由华安插件通过 `ctx.systemPrompt.section` 注册一段常量正文：思考过程使用简体中文；回答语言跟随用户。名字和 order 固定，order 不占用官方 `PLAN_POLICY`（500）。计划模式开关时，官方引导段会从空变为计划文，华安这段保持逐字不变，也不写进每一条用户消息。模型仍用英文思考时，面板照实显示，不另调模型翻译。

### 8.2 对话区呈现

面板位于该回合助手气泡的上方，和工具卡同属这一轮，不另开页面或侧栏。

- 标题固定为「思考」。流式过程中标题旁显示「进行中」。
- 尚无助手正文时，面板展开，内部最高约 40% 视口高度，超出后在面板内滚动，页面跟着最新一行。
- 助手正文一开始到达，面板收成一行「思考 · 已生成」，正文保持可见。用户可以再展开。
- 用户手动展开或收起后，本回合不再自动改这个状态。
- 没有思考内容时不渲染面板。
- 更新不抢焦点，不每收到一个 token 就打断读屏。展开按钮可用键盘操作。
- 面板内文本按纯文本显示，不执行 HTML 或 Markdown 里的脚本。
- 思考文字使用次要颜色，和助手正文区分。面板不显示「已完成百分之多少」。

历史会话重新打开时恢复面板，默认收起，标题为「思考」。实施时先读会话日志：日志里已有 reasoning 块，就从日志投影；没有，则在桥接落点把完整思考写入现有会话记录能带回的字段。不新建一套运行目录。

### 8.3 边界

- 思考面板是模型草稿。它不参与第 5.3 节的完成判断。
- 取消或失败后，已经流到界面上的思考保留，并标成「已中断」。
- 重连后用完整思考文本覆盖同一回合的流式草稿，不追加第二块。
- 日志、导出和复制助手回答时，默认只含正文。思考有单独的复制操作，放在面板里。

## 11. 待批准的默认值

1. 思考面板在正文到达后自动收起。用户手动展开或收起后，该回合不再自动切换。
2. 思考语言靠系统提示要求简体中文。面板显示原文，不翻译。
3. 计划模式只用于 planned，经 `ctx.planMode` 进入。它不限制工具，计划卡上写明这一点。需要确认时由用户点击 `plan-review`。展示后执行由回答者在计划卡出现后提交「按当前护栏自动继续」，不补记用户点击。对话里始终有「退出计划模式」，它作废未回答的评审并退出。
4. 待办不是完成证据。文件和约定的检查才是。
5. 发送受理后返回。5 分钟无新结果才醒目提示。Host 约 15 秒无响应只提示，约 60 秒且有进行中回合才允许结束进程。
6. 目标续轮默认最多 4 轮，并且排在发送解耦之后。
7. 第 2 节列出的锁和官方界面插件保持关闭。
8. `request_input` 的回答回到同一回合的工具结果，不另开一条用户消息。`propose_plan` 只携带一句话目标，计划正文留到 `exit_plan_mode`。
