## 二、P1 缺陷:@点名 HTTP 小工具链路断裂(call_host_tool 未注册)

**现象**:模型收到 `<tool-invoke>` 信封后未按约束首调 `call_host_tool`,两次转而请求 bash(均被拒),最终如实报告工具缺失(诚实,未伪造结果):

> **I cannot invoke `call_host_tool`.** That tool is not exposed to me in this session — my available tool set is `bash, edit, git_*, glob, grep, read, screenshot, web_fetch, write`. There is no `call_host_tool` (and no host-tool bridge binary on `PATH`). So the required first action — calling the `code-review` host tool — cannot be performed from here…

(全文见 `08-model-report-call-host-tool-missing.png`)

**根因(代码级,三环俱在、独缺一环)**:

| 环节 | 状态 | 出处 |
| --- | --- | --- |
| 信封生成(第一动作约束注入) | ✅ 已接 | `huaanwork-host/agent-invoke.ts:94` |
| 会话附件簿(attachHostTool) | ✅ 已接,但 `sessionHostTools` **只写不读** | `agent-invoke.ts:89` → `agent-attachments.ts:13-20` |
| 执行期 policy 门禁(isHostAttached) | ✅ 已接(等着放行) | `huaanwork-guardrails/policy.ts:183` |
| **工具注册(registerCallHostTool)** | ❌ **全仓无生产调用方,仅测试调用** | `agent-tool.ts:123` 定义;唯一调用在 `tests/huaanwork-guardrails/agent-tool.cordis.spec.ts`,其用例 7 的命名即接线契约:「apply() 之后 ctx.tools.register 调用次数为 0(只挂 listener),**registerCallHostTool 才产生一次 register**」 |

**第二处必改点(修复时联动)**:`present-as.ts:116-121` 的会话工具收窄只放行 `ALLOWED_TOOLS ∪ sessionAgentTools(MCP)`——即便补上注册,host-attached 会话的 `call_host_tool` 仍会被 restrict 掉;需为 host-attached 会话增补放行(如 `isHostAttached(attachments, sessionId, name)`)。

**修复草图(供修复轮;本记录只登记,不在 A4-1 范围动手)**:

1. `huaanwork-host/index.ts` 在同步 `huaanworkAgentCatalog.current` 处(现为 :112-128)调 `registerCallHostTool(ctx, snapshot)` 并持 disposer;
2. `present-as.ts` 的 `restrictInternal` 对 host-attached 会话放行 `call_host_tool`;
3. 补 cordis 集成测试:注册后 **attached 会话** schemas 含 `call_host_tool`、**未 attached 会话**不含(保持 per-session 语义;注册全局单工具、执行期仍由 policy 按会话附件放行);
4. 修复后重跑本记录「三、待复测清单」。
